# Исправление логики определения запросов на консультацию

## Проблема
При запросе "Хочу узнать о школе" бот переводил на менеджера, хотя должен был отвечать через ИИ.

## Причина
В методе `_is_consultation_request` была фраза "хочу узнать", которая срабатывала на любые информационные запросы.

## Решение
Улучшена логика определения запросов на консультацию:

### 1. Удалена слишком общая фраза
- Убрано "хочу узнать" из списка фраз для консультации

### 2. Добавлена проверка информационных запросов
Добавлен список фраз, которые НЕ должны считаться консультацией:
- "хочу узнать", "расскажите", "что такое"
- "информация о", "про школу", "про детский сад"
- "какие есть", "сколько стоит", "какие программы"

### 3. Новая логика работы
1. Сначала проверяется, содержит ли сообщение запросы на консультацию
2. Если да, то дополнительно проверяется, не является ли это информационным запросом
3. Если это информационный запрос - НЕ считаем консультацией
4. Если это реальный запрос на консультацию - переводим на менеджера

## Когда считается консультацией
- "консультация", "встреча", "обсуждение"
- "хочу поговорить", "нужна помощь"
- "записаться на консультацию", "записаться на встречу"

## Когда НЕ считается консультацией
- "хочу узнать о школе" ✅
- "расскажите о программах" ✅
- "информация о детском саде" ✅
- "какие есть занятия" ✅

## Результат
Теперь бот правильно обрабатывает информационные запросы через ИИ, а на менеджера переводит только при реальных запросах на консультацию.
